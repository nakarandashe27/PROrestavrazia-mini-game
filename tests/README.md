# Переносимые проверки игры

Этот каталог содержит исходники тестов, запускаемых локально и в GitHub Actions. Нужны Node.js 22 не ниже 22.12 и установленные через `npm ci` зависимости. Команды выполняются из корня репозитория.

```sh
npm test
node tests/fieldwork-checks.mjs
```

## Что запускается

| Команда и файлы | Покрытие |
|---|---|
| `npm test` → `run.mjs` → `physics.ts` | 100 seed × три этапа со словами и один фасадный этап: 400 маршрутов, 4200 находок. Проверяются физическая досягаемость, порядок букв, разные высоты прыжка, восстановление после падения, сохранение находок и очистка ввода |
| `npm test` → `generation-variants.ts` | 300 seed: воспроизводимость геометрии, 30 авторских профилей, десять типов участков, направления фасада, ограничения перепадов и пролётов. Дополнительно проходят 64 коротких фасада с узким логическим окном |
| `node tests/fieldwork-checks.mjs` → `fieldwork.ts` | 900 этапов и 2700 полевых станций: уникальные id, воспроизводимость, безопасные неподвижные опоры и отступы от находок. 30 физических прохождений и 90 взаимодействий; запрет входа в воздухе/паузе, однократное завершение и сохранение результата при восстановлении |
| `fieldwork.ts`, проверки `newSeed()` | 200 случаев повторяющегося источника случайности, отказа crypto и недоступного localStorage. Новый seed остаётся допустимым и не повторяет предыдущий |

Прохождение использует тот же `Engine`, что и игра: команды движения, прыжка и спуска с обновлением физики. Отдельные проверки пограничных состояний намеренно выставляют состояние движка, например падение ниже уровня; это не заменяет прохождение маршрутов переносом персонажа к целям.

Оба runner собирают TypeScript через esbuild в памяти и исполняют полученный модуль в Node. Они не требуют установленного Chrome, Playwright, пути к Codex или файлов за пределами проекта. Заглушка `window.matchMedia` позволяет проверить игровую логику без браузерного рендера. Падение любого утверждения приводит к ненулевому коду завершения процесса.

## Связь с публикацией

Workflow [pages.yml](../.github/workflows/pages.yml) при push в `main` выполняет:

```sh
npm ci
npm test
node tests/fieldwork-checks.mjs
npm run build
```

Только после успешных проверок и сборки публикуется `dist`. Проверки не создают коммитов и не меняют содержимое игры. Папка `dist` — результат сборки, а не часть тестовых исходников.

## Границы автоматической проверки

Этот набор проверяет генерацию, физику и состояние взаимодействий. Он не рисует Canvas, не проходит React-диалоги, не проверяет сенсорные жесты, слышимость звука, внешний вид фасада или PDF в просмотрщике.

Во время разработки отдельно выполнялись браузерные сценарии, холодные автономные запуски, аудиопрогоны и визуальные обзоры. Их результаты описаны в [QA.md](../QA.md) и [POLISH-CYCLES.md](../POLISH-CYCLES.md). Сценарии `v6-*`, `v5-*`, локальные browser runners, снимки PNG, PDF, видео, журналы и архивы остаются локальной историей и не входят в этот репозиторий. Поэтому упомянутый в отчёте локальный файл может отсутствовать в checkout; это не файл, необходимый для `npm test`.

Зелёный workflow подтверждает перечисленные автоматические проверки и успешную сборку. Доступность опубликованного сайта и удобство игры для посетителей проверяются отдельно.
